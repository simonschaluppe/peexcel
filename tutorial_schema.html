Ein neues Excel-Schema prüfen

Schema-Bindings in einem isolierten Ausgabeordner erzeugen, Unterschiede prüfen und die spätere Aktivierung vorbereiten.

Lernziel

Schema-Bindings in einem isolierten Ausgabeordner erzeugen, Unterschiede prüfen und die spätere Aktivierung vorbereiten.

Voraussetzungen: Gespeicherte PEExcel-Exporte; keine Excel-Installation erforderlich.

Einmalig im Repository installieren: python -m pip install -e ".[publication]". Zum eigenen Ausführen das Notebook im geklonten Repository öffnen und die Zellen von oben nach unten ausführen. Die Website zeigt gespeicherte Ausgaben; sie führt keinen Python-Code im Browser aus.

Tutorial-Notebook herunterladen · Alle Tutorials

1. Version und Quelle festlegen

Ein neues Excel-Schema verändert Variablendefinitionen, Zeitreihen und Berichte. Wir verwenden einen vorhandenen Schemaexport und schreiben ausschließlich in einen lokalen Prüfbereich. Das aktive Paket-Schema wird dabei nicht überschrieben.

Python-Code anzeigen 
from pathlib import Path
import sys
import pandas as pd
from IPython.display import display

# Im geklonten Repository ausführen, z. B. aus website/ oder notebooks/.
ROOT = next((p for p in (Path.cwd(), *Path.cwd().parents)
             if (p / "src/pexl").is_dir() and (p / "pyproject.toml").is_file()), None)
if ROOT is None:
    raise FileNotFoundError("Bitte das Notebook innerhalb des peexcel-Repositorys öffnen.")
sys.path.insert(0, str(ROOT / "src"))
sys.path.insert(0, str(ROOT / "scripts"))
OUTPUT = ROOT / "notebooks/local_exports/tutorials"
OUTPUT.mkdir(parents=True, exist_ok=True)
from pexl import schema
from pexl.schema.current import SCHEMA_VERSION
VERSION = "1.13.1_dev"
QUELLE = ROOT / f"data/exports/schema_{VERSION}.xlsx"
ALT = ROOT / "data/schemas/v1_12_7"
PRUEFUNG = OUTPUT / "schema_pruefung"
assert QUELLE.is_file() and ALT.is_dir()
print("Aktives Schema:", SCHEMA_VERSION)
print("Zu prüfender Export:", QUELLE.name)

2. Bindings getrennt erzeugen

dataset_dir und generated_dir sind beide ausdrücklich gesetzt. Ohne generated_dir würde die Funktion in das Paketverzeichnis schreiben. Wiederholung ersetzt nur Dateien im lokalen Prüfbereich.

Python-Code anzeigen 
ergebnis = schema.create(
    QUELLE, dataset_dir=PRUEFUNG / "daten", generated_dir=PRUEFUNG / "generated",
    version=VERSION, replace_files=True,
)
display(pd.Series({"Schema": ergebnis.schema_module.name,
                   "Zeitreihen": ergebnis.timeseries_module.name,
                   "Reports": ergebnis.report_module.name}))

3. Unterschiede prüfen

Die vorhandene Vergleichsfunktion prüft die Dataset-Verzeichnisse. Hinzugefügte oder entfernte Variablen, Einheiten und Metadaten müssen fachlich geprüft werden; erfolgreiche Codegenerierung allein reicht nicht.

Python-Code anzeigen 
from pexl.validate.schema import diff_schema_dirs, schema_diff_to_markdown
from IPython.display import Markdown
unterschiede = diff_schema_dirs(old_dir=ALT, new_dir=ergebnis.dataset_dir)
vergleich = schema_diff_to_markdown(unterschiede, value_format="None")
(PRUEFUNG / "vergleich.md").write_text(vergleich, encoding="utf-8")
# In der Seite nur einen Auszug anzeigen; der vollständige Bericht liegt lokal vor.
display(Markdown(vergleich[:5000]))

4. Aktivierung bewusst vornehmen

schema.create validiert bereits den Import der erzeugten Module. Nach fachlicher Prüfung werden Dataset und generierte Module in die vorgesehenen Versionsverzeichnisse übernommen und die Importe in src/pexl/schema/current.py angepasst. Dies ist eine gesonderte Repository-Änderung, kein Nebeneffekt dieses Tutorials.

Anschließend Kernel neu starten, repräsentative Projektexporte einlesen und im Repository python -m pytest ausführen. Dabei Importwarnungen, neue Variablen und Standardberichte kontrollieren. Bei reiner Reportpflege die bestehende Codegenerierung verwenden, keine zweite Berichtsregistry aufbauen.

Ergebnis

Du erhältst geprüfte Python-Module und einen Vergleichsbericht im lokalen Prüfbereich. Das aktive Schema bleibt unverändert, bis du die geprüfte Version ausdrücklich übernimmst.
